# ToonTest_01 — Blender 3D 툰 셰이딩 vs r30 Live2D 얼굴 (기술 검증, 2026-11-11)

## 범위와 보호

- 이 폴더만 새로 만들었다: `BlenderSource/Characters/MainGirlfriend/Experiments/ToonTest_01/`.
- 원본 `Models/MainGirlfriend_Face_v2.blend` 는 복사만 했다 (SHA-256 `spec/source_face_v2.sha256`, 작업 뒤 같음 확인). r30 cmo3·moc3·PSD, Unity 씬·프리팹, 공통 아이템 시스템·DB, 패키지는 바꾸지 않았다.

- Cubism 소체·의상 작업은 일시 중단 (다리·발·슬리퍼 후보와 검증 스크립트는 그대로 보존).

## 2. 실험 내용

- 비율: 머리 묶음을 턱 기준 0.731 배, 몸을 Z 1.134 배 → 4.12 등신, 키 1.65 m 유지. 눈 크기·간격·높이, 코·입·눈썹 높이를 r30 비율로 이동.
- 피부: Diffuse → Shader to RGB → 3단 램프 (그늘 / 약한 그늘 / 기본 / 밝음, 전환 폭 0.06–0.08) → 방사 (조명 영향은 램프만).
- 눈: r30 `Iris_R`+`Iris_Rim_R`+`Pupil_R` 그림을 정면 평면 UV 로 홍채 디스크에 붙임 (왼눈은 좌우 반전), 기존 동공·하이라이트 메시는 숨김 (그림에 포함).
- 머리카락: 3단 램프 + 위쪽을 향한 면의 하이라이트 띠 (법선 Z 0.55–0.80 × 카메라 정면) + 가닥 무늬 (늘인 웨이브 텍스처, 22 %).
- 외곽선: 뒤집힌 껍질 (Solidify, 법선 반전, 뒷면 컬링 갈색), 머리카락 1.6 mm (진한 적갈색), 피부 1.1 mm (갈색).
- 카메라: 정사영, r30 얼굴 자르기 (700, 0)–(1360, 860) 와 같은 배율·위치.

![전신 비교](renders/compare_body_v2.png)

결론: **툰 셰이딩 경로 (램프·홍채 그림·외곽선·정사영) 는 동작하고 Unity 로 옮길 수 있다. 그러나 지금 3D 모델은 블록아웃이라 r30 얼굴 품질과 비교할 단계가 아니다.** 품질 차이의 대부분은 셰이더가 아니라 머리카락·얼굴형 모델링과 손으로 그린 텍스처 (그림자 맵·하이라이트) 에서 온다. 픽셀 차이가 아니라 그림으로 봐도 r30 과 같은 캐릭터로 읽히는 것은 정면의 눈 정도다.

## 4. Blender 전용 vs Unity URP 에서도 되는 것

| 기능 (이번 실험) | Blender | URP 17.6 에서 |
|---|---|---|
| Shader to RGB + Color Ramp | EEVEE 전용 노드 | 가능: Shader Graph Custom Function (`GetMainLight`) 또는 HLSL Unlit 셰이더에서 N·L → 램프 텍스처 (1D) 조회 |
| 뒤집힌 껍질 외곽선 (Solidify) | 모디파이어 | 가능: 같은 셰이더의 두 번째 패스 (`LightMode = SRPDefaultUnlit`, Cull Front, 법선 방향 정점 밀기, 화면 크기 보정). 날카로운 모서리는 부드러운 법선을 Blender 에서 정점 색·UV 로 구워 넘김 |
| Freestyle / Line Art (안쪽 선) | 가능 (이번엔 안 씀) | 실시간 불가 → 안쪽 선은 텍스처에 그리거나 깊이·법선 기반 후처리 (깊이 텍스처를 켜야 함, 모바일 비용) |
| 웨이브·노이즈 절차 텍스처 | 가능 | 텍스처로 구워서 사용 |
| 홍채 그림·볼터치 투명 | 가능 | 가능 (Unlit 투명, 그리기 순서 지정). 볼터치는 얼굴 텍스처에 구우는 편이 모바일에 유리 |
| 법선 기반 머리카락 하이라이트 띠 | 가능 | 가능 (Shader Graph). 실제로는 하이라이트 텍스처 / 맷캡이 r30 에 더 가까움 |
| 앞머리 그림자 | (안 함) | 얼굴 그림자 맵 (SDF) 이나 머리카락 전용 그림자 패스 — 직접 구현 필요 |
| EEVEE 부드러운 그림자·AO | 가능 | 쓰지 않음 (툰 화풍에 방해, 모바일 비용) |

## 5. 2D 얼굴 활용 방식 비교

| | A. 3D 얼굴에 2D 스타일 텍스처·블렌드셰이프 | B. 3D 전신 → Live2D 얼굴 클로즈업 전환 | C. Blender 애니메이션을 2D 스프라이트로 굽기 |
|---|---|---|---|
| 외형 품질 | 정면은 높일 수 있음 (r30 눈 그림 재사용 확인). 3/4·측면에서 평면 눈·볼이 어색해지기 쉬움, 머리카락 모델링 품질이 결정적 | 클로즈업은 **r30 그대로 최고 품질**. 3D 장면과 얼굴 화풍이 달라 보일 위험 → 전환 연출·같은 색 규격 필요 | 렌더 품질 그대로 (2D 처럼 보임), 각도·동작이 미리 정한 것뿐 |
| 제작 난이도 | 높음: 얼굴 토폴로지, 표정 셰이프키, 얼굴 그림자 맵, 눈 시선 | 중간: Live2D 얼굴 모델은 이미 있음 (r30). 전환 카메라·화면 합성, 같은 의상·헤어를 두 렌더러에 맞추는 일 | 중간: 굽는 파이프라인은 쉬움, 동작마다 다시 굽기 |
| Cursor 자동화 | 셰이더·머티리얼·렌더·검사는 Python/C# 로 자동화 쉬움, 얼굴 모델링·셰이프키 조형은 사람 손이 큼 | Live2D 쪽은 기존 스크립트 (s22–s30) 재사용, Unity 전환은 C# 자동화 쉬움. Cubism 편집기 작업은 GUI 라 반자동 | Blender 백그라운드 렌더로 거의 전부 자동화 가능 (이번 실험과 같은 방식) |
| 의상·헤어 추가 비용 | 3D 에셋 1벌 | 3D 1벌 + (클로즈업에 보이면) Live2D 헤어·상의 윗부분 1벌 → **두 번** | 의상 × 동작 × 각도 조합만큼 다시 굽기 → 조합 폭발 |
| 애니메이션 재사용 | 높음 (리그 하나로 모든 동작) | 3D 동작 재사용 + Live2D 표정 재사용 (`ExpressionIntent` 로 공통) | 낮음 (구운 프레임은 의상 바뀌면 못 씀) |
| 모바일 성능 | 3D 1 체 + 외곽선 패스 (드로우 2 배), 투명 레이어 오버드로 | 클로즈업 중 Cubism 1 모델 추가 (A0 측정: 모델당 Cubism 갱신 0.2–0.4 ms), 렌더 텍스처 한 장 | 텍스처 메모리가 큼 (프레임 수 × 해상도), GPU 부담은 낮음 |
| 기술 제약 | 툰 얼굴 3D 의 고질 문제 (측면 눈·입, 얼굴 그림자) 해결 필요 | 얼굴과 몸이 다른 시스템: 머리 각도·조명·색 맞춤, 전환 순간 이음새 | 런타임 의상 교체·실시간 반응 불가 |

권장: **B 를 기본 연출 방식으로, A 를 장기 개선으로.** 레이싱·미니게임·전신 동작은 3D (A 의 셰이딩 경로), 얼굴이 화면을 채우는 장면은 r30 Live2D 얼굴로 전환. C 는 고정 연출 (로딩·튜토리얼 컷) 에만.

## 6. 공통 아이템 시스템 재사용

- 그대로 재사용: `ItemDefinition`·`covers`·`EquipmentState`·`AppearanceResolver`·`ResolvedAppearance` (렌더러 독립), 색 (`skin`·`hair`·`eye`), `ExpressionIntent` (13장), 7-4 신발 표시 규칙 (3D 는 `Body_Foot_L/R` 메시 끄기).
- 렌더러별로 채울 것: `AssetMapping(model3d)` (메시·소켓·`hidesRegions`·머티리얼 채널), B 방식이면 같은 아이템의 `AssetMapping(cubism)` (얼굴·헤어·머리핀·상의 윗부분). 한 아이템이 두 렌더러 매핑을 함께 가져야 클로즈업 전환이 맞는다 → 매핑 누락 검사 (`RendererSupportChecker`) 필요.
- 결정 필요 (05·00 문서 미정과 연결): 클로즈업에 보이는 아이템 범위 (헤어·머리핀·상의 목둘레까지?), Live2D 얼굴 모델의 분리 (얼굴만 moc3 로 줄일지).

## 7. 모바일 성능 주의

- 외곽선 두 번째 패스는 드로우와 정점 처리를 두 배로 함 → 머리·몸·의상 메시 수를 줄이고 SRP Batcher 호환 셰이더로.
- 투명 (눈 그림·볼터치·속눈썹) 은 오버드로·정렬 문제 → 가능하면 얼굴 텍스처에 굽고 알파 클립.
- 지금 모바일 설정은 MSAA 꺼짐·렌더 배율 0.8 → 얇은 갈색 선이 계단·깜빡임이 생기기 쉬움. 선 두께 화면 보정 + MSAA 2× 또는 FXAA 검토 (설정 변경은 승인 뒤).
- 얼굴에 실시간 그림자를 받으면 툰 화풍이 깨지고 비용도 큼 → 얼굴 그림자 맵 방식.
- B 방식: 클로즈업 동안만 Cubism 모델을 켜고 렌더 텍스처 해상도를 제한, 3D 와 Live2D 를 동시에 오래 갱신하지 않기.
- 레이스 화면 (여러 선수): 상대 선수는 LOD·외곽선 끄기·얼굴 텍스처 축소.
